Described only

Public opportunity intake

Live intake does not depend on a SAM.gov API key. The edge intake worker pulls SAM.gov’s public Contract Opportunities CSV extract (pullSamPublicExtract in government-ops-spine/src/edge/public-extract.ts) and reads Grants.gov for grant notices. Foundry remains the companion opportunity-intelligence and execution platform. A SAM.gov Opportunities API key is optional and is not required for that public-extract path.

When a record reaches the spine, OpportunityIntakeService checks schema 1.0.0, compacts text, sorts provenance, and SHA-256 hashes a canonical JSON form that ignores retrieval timestamps. The repository classifies the write as created, unchanged, amended, or cancelled. An unchanged hash does not start a new revision. Active new or changed records can be analyzed inside the spine process, which stores them in Postgres.

None of that storage is reachable from these pages. The opportunities view reads a static sample file that ships with this site.

Requirement extraction

parseOpportunity joins the summary and raw text, then splits on sentence boundaries and newlines. Fragments shorter than 24 characters are dropped. A sentence is kept when it contains must, shall, required, requires, minimum, maximum, eligible, deliver, demonstrat, comply, or capable.

It is marked mandatory when it contains must, shall, required, minimum, or maximum. Otherwise it is optional. Category is the first matching rule: security, compliance, validation, delivery, interface, data-rights, performance, otherwise functional.

Standards lines mention ISO, NIST, FAR, DFARS, NDAA, ASTM, IEEE, OSHA, standard, or regulation. Confidence starts at 0.45, adds 0.04 per extracted requirement, subtracts 0.15 when review is required, and is clamped between 0.20 and 0.95. Review is required when any provenance authority is not official, or when no requirements were extracted. This is a keyword heuristic, not a language model. The demo marks its own wrapper as aggregator provenance, so review is required.

Build specification

generateBuildSpecification copies the mission summary into the objective and sets approvalState to draft. This site cannot move that state to technical review or authorized.

Components come from fit tags, plus one component name per mandatory requirement. Interfaces are the statements categorized as interface. Tests are the validation statements, plus an acceptance test named for each mandatory requirement. The evidence list is fixed: a requirements traceability matrix, architecture and interface documentation, a test plan and test results, compliance evidence, and a configuration and provenance manifest.

Execution zones are the active list from zones.ts unless the spine process sets EXECUTION_ZONES. This Worker does not set that variable, so the default list is used: KERNEL, TREASURY, AI, SECURITY, XR, DATA, CLOUD, GOVERNMENT_OPS, PLATFORM, MONITORING.

Capability matching

matchCapabilities tokenizes each requirement into lowercase tokens of length 4 or more. A capability’s score is how many of its tags appear in those tokens, divided by its tag count. The highest score wins. At least 0.70 is reuse, at least 0.35 is adapt, and anything lower is build.

The TypeScript union also allows partner. This function does not return it. A zero score says a build or partner analysis is required, and the disposition is still build.

The catalog in the demo is fictional and exists only to exercise that function. It is not the spine’s GitHub, Docker, or filesystem index, and it is not a record of delivery.

Plan

createBrainPlan always emits five tasks, and externalActionsBlocked is always true:

  • TASK-001 research, no dependencies
  • TASK-002 design, depends on TASK-001
  • TASK-003 software, depends on TASK-002
  • TASK-004 simulation, depends on TASK-003
  • TASK-005 documentation, depends on TASK-004

Each task takes an execution zone by index from the active list. With the default list, those zones are KERNEL, TREASURY, AI, SECURITY, and XR. This site does not set EXECUTION_ZONES.

Controlled PDF and DOCX rendering

ControlledDocumentRenderer loads an engineering artifact from Postgres, draws a PDF with pdf-lib or a DOCX with the docx package, and SHA-256 hashes the file bytes. The stored package sets externalActionBlocked to true. Its release state is release_candidate only when the artifact’s approval state is already technical_review. Otherwise it is internal_review.

This site does not render PDF or DOCX files and does not open Postgres. The demo hashes the JSON of the analysis, specification, matches, and plan with SHA-256, using the same algorithm on a different subject. That digest is not a document export.

Hard gate

assertExternalActionAuthorized throws unless a token starts with AEGENTIX-AUTH-. The checked actions are submit_offer, file_patent, commit_funds, and external_representation. The demo calls the function with no token and shows the error. This site has no token field. A token sent by a client is ignored and is not stored.

Foundry’s current submission transport is local and simulated. It does not send email, call a portal, or submit to an external API. The spine’s correspondence approval stores only a SHA-256 of a token and does not expose a send endpoint. None of those paths are mounted on this Worker.

Runs here

Requirement parsing, the draft specification, matching against the sample catalog, the five-task plan, a SHA-256 of that JSON, and the authorization check with no token.
