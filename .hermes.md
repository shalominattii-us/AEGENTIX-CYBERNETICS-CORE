# Hermes Orchestration — AEGENTIX Project Policy

## Delegation Model
- **Model:** `upstage/solar-pro4:free` (primary)
- **Provider:** `nous`
- **Max concurrent children:** 10
- **Max iterations per delegate:** 250

## Agent Surfaces
Hermes delegates operating on this device have access to:
- `terminal` — shell commands and process management
- `file` — read/write/search/patch
- `code_execution` — sandboxed Python
- `delegation` — subagent spawning (within max_concurrent_children)

Delegates do NOT have browser, computer_use, or web access unless explicitly granted for a specific task.

## Orchestration Primitives
This project uses three Hermes-native primitives, replacing the legacy PowerShell orchestration layer:

1. **delegate_task** — spawns independent agent workers for parallel execution. Used for the 5-agent swarm (Visionary, Guardian, Builder, Wise, Executor) and for ad-hoc tasks.
2. **cronjob** — scheduled jobs. Replaces `orchestrator/task-scheduler.ps1`. Used for recurring security scans, metrics collection, and swarm consensus rounds.
3. **Kanban** — durable work queue. Replaces the empty `orchestrator/` directories. Columns: Inbox → Swarm Consensus → Execution → Verification → Security → Observability → Done.

## Governance Rules
- All agent actions require evidence (a file, log, or structured result) and verification.
- The Guardian agent (security) must approve any action that touches: security configs, Falco rules, port assignments, process spawning, network egress.
- Swarm consensus (`autonomous_swarm.py` `SwarmManager.swarm_think()`) is the authority for cross-agent decisions. Hermes delegates should read `swarm_state.json` and `active_swarm_manifest.json` before making swarm-level decisions.
- Integrity scores are tracked per-agent. Any delegate whose integrity score drops below 50 must stop executing and report to the Visionary.

## Security Boundaries
- Falco rules in `security/falco-aegentix-rules.yaml` are the ground truth for container-level security events.
- `security/agent_security_engine.py` provides behavioral anomaly detection (5 indicators).
- Port whitelist: 80, 443, 9090, 3001, 9093, 8080, 7070-7073. Any delegate proposing a new listening port must go through the Guardian.
- Secrets live in `.env` — never commit, never read into delegate context.

## Observability Integration
- Prometheus scrapes agent metrics. Delegates that produce metrics should expose them on port 9090 or write to the Prometheus pushgateway.
- Grafana dashboards are provisioned from `monitoring/grafana-dashboards.yml/`.
-Alertmanager routes to the Guardian for incident response.

## Runtime Services
- Runtime agent (port 8080) is the HTTP control plane for the swarm.
- HUD (port 3000) is the human-facing dashboard.
- GAIA (port 8090) is the intelligence network node — not yet running.

## File Conventions
- Agent manifests: `agents/<role>/manifest.json` — declares role, authority, execution model, evidence/verification requirements.
- Swarm state: `swarm_state.json`, `active_swarm_manifest.json` — read before swarm-level decisions.
- Workflow results: `orchestrator/workflows/workflow-*.json` — legacy, being migrated to Kanban.
- Event log: `orchestrator/events/events.log` — legacy, being migrated to Hermes session transcripts.

## What Hermes Owns
Hermes is the orchestration brain. It does NOT replace the swarm agents — it coordinates them. The 5 swarm agents retain their `think()`/`act()` loops and integrity scoring. Hermes adds: parallel delegation, scheduled jobs, durable work queues, and cross-agent consensus routing.

## What Hermes Does NOT Do
- Does not modify `.env` or any file containing secrets.
- Does not kill running processes without Guardian approval.
- Does not change the swarm's integrity scoring logic.
- Does not delete the legacy PowerShell orchestration files until the Hermes replacement is verified as functional.
